# Phase-programmable optical multiports

Inverse design of a coherent 1 × 3 splitter and a compact 3 × 3 decoder for phase-controlled optical routing and power allocation.

## One passive device, multiple output states

A fixed multiport converts the relative phases of coherent inputs into an output power distribution. The device geometry stays unchanged when the programmed state changes. A coherent splitter supplies three input paths; two independent relative phases control their interference in the decoder.

The design strategy combines **multiwavelength inverse design** with **phase-conjugate routing**: optimize the decoder's single-port responses for balanced splitting, then conjugate their output phases to form routing inputs in the reciprocal direction. This separates the passive device design from its phase code. The same physical interface supports routing and power allocation, subject to the states accessible to the fixed transmission matrix.

This repository provides the two **2D optical inverse-design workflows** underlying that approach. It includes shared simulation and optimization modules, notebook entry points, complete optimizer checkpoints, and broadband numerical exports. It does not include fabrication files, experimental data, or the separate allocation-search and hardware-control workflows.

## Included designs

| Setting | Coherent splitter | Three-port decoder |
| --- | --- | --- |
| Ports | 1 input, 3 outputs | 3 inputs, 3 outputs |
| Design region | 2.08 × 2.88 µm | 2.88 × 2.88 µm |
| Pixel array | 26 × 36 | 36 × 36 |
| Independent parameters | 26 × 18, mirrored about y = 0 | 36 × 36 |
| Optimization wavelengths | 1455–1545 nm, 19 points | 1470–1530 nm, 13 points |
| Adam updates | 50 | 60 |
| Design objective | Equal power and aligned output phases | Equal splitting for each single-port input |

Both designs retain an **80 nm pixel pitch**, a **10 nm local solver mesh**, and **150 nm waveguides** from the supplied 2D model. These are distinct from a 3D silicon-on-insulator implementation. Material, source, and optimizer settings are explicit in `configs/`.

## Getting started

Use Python 3.10–3.12 in a fresh environment. From the repository root:

```bash
python -m pip install -r requirements.txt
python -m pip install -e ".[notebooks,dev]"
multiport preview --config configs/splitter.yaml
multiport preview --config configs/decoder.yaml
```

Previewing geometry is local and does not submit simulations. For interactive use, launch `jupyter lab` and open `notebooks/01_splitter.ipynb` or `notebooks/02_decoder.ipynb`.

Optimization and validation use the [Tidy3D cloud service](https://docs.flexcompute.com/projects/tidy3d/en/latest/). Configure your own account with `tidy3d configure`. Cloud jobs require available credits; a local GPU is not required. Each decoder update evaluates three excitations and their adjoint work.

```bash
multiport optimize --config configs/splitter.yaml --submit
multiport evaluate --config configs/splitter.yaml --submit
multiport optimize --config configs/decoder.yaml --submit
multiport evaluate --config configs/decoder.yaml --submit
```

## Resume and inspect

Results are written to `results/splitter/` and `results/decoder/`. To limit one session to ten additional updates, add `--max-steps 10` to `optimize`. Run the same command again to resume automatically.

Every completed update saves the independent parameters, full design matrix, gradients, objective history, **Adam moments and step counters**. A new account can continue from the local checkpoint after authentication is reconfigured. Keep the same configuration and dependency versions; an interrupted, incomplete cloud step may need to be repeated. Credentials are never stored in checkpoints.

Final validation exports a 501-wavelength spectrum, complex mode amplitudes, integrated flux, and field/geometry figures. In `validation/transmission.npz`, the complex array uses **output × input × wavelength** order. Flux is exported separately because it contains power, not complex phase. See [methods and file conventions](docs/methods.md) for the objectives, normalization, and checkpoint details.

## Verification and scope

```bash
python -m pytest
```

Tests run offline and cover geometry, objective gradients, numerical exports, and uninterrupted-versus-resumed Adam updates. Local checks do not establish cloud convergence or reproduce the manuscript's performance figures. Optimized geometries and cloud results are generated by running the workflows.
